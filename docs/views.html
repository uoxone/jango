Views

Request in, response out

A view is a function. It borrows the request for as long as it runs, and it returns the response.

A function

use crate::settings;
use ongo::prelude::*;

pub fn home(req: &Request) -> Response {
    render!(req, "home.html", {
        "addr" => settings::ADDR,
    })
}

pub fn song(req: &Request) -> Response {
    Response::text(req.param("id").unwrap_or(""))
}

ongo::prelude brings in Request, Response, Router, Method, routes!, and render!.

Keep the function light. It runs on the same thread that holds the connection.

Read the request

CallGives you
req.method()GET, POST, PUT, PATCH, DELETE, HEAD, or OPTIONS
req.path()The path, such as /song/12
req.query("q")The value of ?q=soup
req.param("id")The <id> segment from the route
req.header("accept")A header. The name ignores ASCII case.
req.body()The raw body bytes
req.body_str()The body as text, when it is UTF-8

In ?q=a=b&q=second&flag, query("q") is a=b and query("flag") is an empty string. The first value wins. OnGo leaves %20 as %20.

A missing query, parameter, or header is None. A body that is not UTF-8 makes body_str() return None. The bytes are still there in body().

Answer

CallStatusContent type
Response::text("hi")200text/plain; charset=utf-8
Response::html("<p>")200text/html; charset=utf-8
Response::json("{}")200application/json; charset=utf-8
Response::status(201, "created")the code you passtext/plain; charset=utf-8
Response::redirect("/next")302an empty body and a Location header

Response::status accepts codes from 100 through 599. A HEAD request receives the headers, including Content-Length, and an empty body.

OnGo reads GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS. HTTP/1.1 stays open for the next request. HTTP/1.0 closes unless the client sends Connection: keep-alive. Send Connection: close when you want the conversation to end.

The body arrives with Content-Length, up to 2 MB. A chunked body is refused. A request may carry up to 32 headers.
