Ship

One file

Your machine compiles. The server only runs the file.

Build it

ongo build nava

The folder you upload is here:

nava/build/nava
nava/build/static

Copy that folder to the server and run the program from inside it:

./nava

Cargo and rustc stay behind. The binary links to the system libc, which Linux already has. Build it on a machine whose glibc is close to the server's.

Let the world in

Before you upload, set ADDR in src/settings.rs:

pub const ADDR: &str = "0.0.0.0:8000";

127.0.0.1 answers only the machine it is running on. 0.0.0.0 answers the network. Use an IPv4 address such as 127.0.0.1:8000 or 0.0.0.0:8000.

Take the static folder with you

HTML is inside the binary. ongo build copies static/ next to the program, so pictures, video, and style.css are already in build/static. OnGo looks in the current directory first, then next to the program.

How it listens

OnGo speaks HTTP itself: epoll, one thread per core, and SO_REUSEPORT. A small response walks a short path.

On one machine, a small release build did about 400,000 requests a second with 8 keep-alive connections, and about 975,000 when the requests were sent in a batch.

Views share the thread that holds the connection. A slow view holds that thread. Keep the work small, and the server stays quick.
