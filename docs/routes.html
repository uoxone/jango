Routes

One line, one page

src/urls.rs is the whole map. A path on the left, a view on the right.

The map

use crate::views;
use ongo::prelude::*;

pub fn urlpatterns() -> Router {
    routes! {
        "/" => views::home,
        "/about" => views::about,
        "/song/<id>" => views::song,
    }
}

A trailing comma is fine. An empty routes! {} is a router with no pages, so every path answers 404.

The new project wires this table in src/main.rs:

let app = urls::urlpatterns().templates(templates::load);
ongo::run(settings::ADDR, app).expect("ongo");

Exact paths

/about and /about/ are two different doors. /About is a third. The query string is not part of the path, so /song/7?x=1 still matches /song/<id>.

A piece of the path

Write <id> where one segment should be captured. /song/12 gives the view req.param("id") as "12".

"/song/<id>" => views::song,
"/u/<user>/song/<id>" => views::playlist,

A capture is one segment. /song/12/live does not match /song/<id>. A name is ASCII letters, digits, and _, as in <id> or <_id>. A route can hold up to 8 captures.

These paths are refused when the router is built:

  • a path that does not start with /
  • an empty segment, such as /song/<id>/
  • a broken capture, such as /song/<id or /song/<>
  • the same path registered twice

When two routes could match

A fixed path is chosen before a pattern. With both /song/live and /song/<id>, a request for /song/live takes the fixed one.

Patterns are tried in the order you wrote them. The first one that fits the path is the one that runs.

A missing page

An unknown path returns 404 and the words Not Found. You can choose another view:

fn missing(req: &Request) -> Response {
    Response::status(404, req.path())
}

let app = urlpatterns().not_found(missing);
